# Repository cleanup audit

## Source of truth

- `packages/server/`: current FastAPI server source.
- `packages/web/`: current iPad/web UI source.
- `packages/contracts/`: shared contracts used by workspace packages.
- `tools/`: local build/deploy helpers. `pollipi_fleet_deploy.py` is dry-run first and must not be used as an implicit live deploy.
- `docs/`: operational notes for field fleet deployment.

## Generated artifacts

- `dist/pollipi_api_server.py`: deployable single-file server artifact generated from `packages/server`.
- `packages/web/dist/`: Vite web build output.
- `packages/web/public/build-info.json`: generated by `pnpm build:web` and copied into the web build.

These artifacts can be regenerated, but they remain part of the deployment workflow until all five Pi devices are known to run the same packaged artifact.

## Legacy / compatibility

- `pollipi_api_server.py`: root-level legacy server kept for compatibility.
- `web/`: root-level legacy web assets kept for compatibility.
- `legacy/`: compatibility material, if present.

Do not delete these until the five Pi devices are confirmed to use the packaged artifact and the compatibility path is intentionally retired.

## Cache / local metadata

- `__pycache__/`, `.pytest_cache/`, `.mypy_cache/`, `.ruff_cache/`
- `node_modules/`
- `.venv/`
- OS metadata such as `.DS_Store`, `Thumbs.db`, `Desktop.ini`, and `._*`
- generated local build outputs such as `dist/`, `packages/web/dist/`, and `packages/web/public/build-info.json`

These should stay ignored and should not be committed.
